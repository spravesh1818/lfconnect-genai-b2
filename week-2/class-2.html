Concept 01

What Is a Token?

Before a model predicts anything, a tokenizer has already chopped your text into tokens — sub-word chunks, not letters or whole words.

  • The tokenizer draws from a fixed vocabulary of common chunks: whole words, word pieces, punctuation, even single characters.
  • Because it splits below the word level, the model can handle rare words, typos, and new languages — no infinite vocabulary needed.
  • A short, common word usually fits in a single token; longer or unusual ones split across two or more.
  • Roughly, 1,000 tokens ≈ 750 English words — though code, non-English text, and numbers tokenize less efficiently.

Concept 02

From Probabilities to a Chosen Word

The model never just outputs one answer for the next token — it ranks its entire vocabulary by probability first.

  • That ranked list has a name: logits — a function called softmax turns them into the percentages you see here.
  • From there, a sampling strategy picks one token from the distribution, and it won't always grab the top choice.
  • Two dials shape that pick: temperature and top-p. Both are up next.
Concept 03

Temperature: the Randomness Dial

Temperature doesn't change what the model knows. It just changes how boldly it's willing to gamble when picking the next token.

  • Low temperature (≈0–0.3): sharpens the distribution — the top choice wins out, so output stays focused and repeatable.
  • High temperature (≈1.0–2.0): flattens that same distribution, giving lower-ranked tokens a real shot — expect output that's varied and surprising.
  • As a default: keep temperature low for factual Q&A or code, and turn it up for brainstorming or creative writing.
  • You set temperature per API call, as a request parameter — it isn't baked into the model itself.
temperature = 0.7
A middle-ground setting: mostly coherent, with a little room to surprise you.
See It In Action

Same Prompt, Two Temperatures

Prompt: "Finish this sentence: The old lighthouse keeper opened the door and saw..."

temperature = 0.1 — deterministic
"...saw that the light was still working, just as it had every night for thirty years."

Run it five times, and you'll get nearly the same sentence each time.
temperature = 1.6 — wild
"...saw a raccoon in a captain's hat, arguing with the fog about maritime law."

Run it five times, and you'll get five wildly different, occasionally incoherent, scenes.

The lesson: temperature isn't manufacturing creativity out of nothing — it's changing how far the sampler wanders from the model's most likely guess. Crank it too high, and fluency itself starts to break down.

Concept 04

Top-p: a Different Kind of Cutoff

Instead of reshaping the whole curve like temperature does, top-p (nucleus sampling) trims the candidate pool by cumulative probability.

How it works

Starting with the highest-probability candidate, the model keeps adding more until they add up to p (e.g. 0.9) — then it samples only from that shortlist.

Why use both

Teams often combine the two: temperature sets "how sharp," top-p decides "how many options even make the table."

  • Set top-p to 1.0 and the whole vocabulary's in play; drop it to 0.1 and you're sampling from a narrow, high-confidence shortlist.
  • Most APIs will let you set both, though in practice teams usually tune one and leave the other at its default.
Concept 05

The Context Window

A model can only "see" a fixed number of tokens at once, and that budget gets split three ways: system prompt, conversation history, and the model's own output.

  • Depending on the model, that window might hold a few thousand tokens, or well over a hundred thousand.
  • Once you hit the ceiling, something has to give: the oldest turns get dropped, summarized, or truncated, and the model just can't see them anymore.
  • A bigger window doesn't mean the model uses it well, either — details buried in the middle of a huge prompt can still slip past it.

Concept 06

Cost & Latency: Tokens Are the Meter

Providers bill you per token, usually at separate rates for input versus output — and the more tokens involved, the slower your response tends to be.

Prompt shapeApprox. input tokensEffect
Short question, no history~20Fast, cheap
+ 10-turn chat history~1,200Slower, more expensive
+ pasted document context~6,000Noticeably slower, priced accordingly
  • Cut the unnecessary history or pasted text, and you're pulling a direct lever on both cost and response time.
  • Ask for a longer output — "write 2,000 words," say — and you'll add latency too, since generation happens one token at a time, in sequence.

Counting Real Tokens, Live

# tokenize locally — no API call required
import tiktoken
enc = tiktoken.get_encoding("cl100k_base")
tokens = enc.encode("Generative AI is transformative.")
print(len(tokens), tokens[:5])
# → 5 ['Gener', 'ative', ' AI', ' is', ' transformative']

  • Then it sends the same prompt to the API twice, once at temperature 0.1 and once at 1.2, and prints both completions side by side.
  • The last cell takes a published per-token price and estimates what a sample request would cost.
Common Pitfalls

Tokens & Sampling Myths

"Temperature 0 is always identical"

It's close to deterministic — though ties and backend nondeterminism can still sneak in tiny variation between calls.

"Tokens = words"

A token is a sub-word piece, and punctuation, whitespace, and word fragments all count as one too.

"More context is always better"

A larger context costs more and runs slower, and it still doesn't guarantee the model pays even attention to everything inside it.

"Higher temperature = smarter answers"

More varied, sure — but not more correct. Higher temperature can just as easily introduce errors.
